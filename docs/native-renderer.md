# Native renderer

`mermaid-trace-rs/` contains the Rust library and a JSON-lines executable. The Node watch host keeps one process alive across saves. The browser receives static SVG and the independent activation library; it runs no renderer today.

Use Rust 1.95+ (tested with 1.98.0), Git, Node 24 and pnpm 11.28.0:

```sh
make native-build
make native-test
make preview ARGS='watch docs/examples/watch-preview.md'
```

The bootstrap script clones [our Merman fork](https://github.com/Nek/merman) into ignored `mermaid-trace-rs/vendor/merman/` and checks out exact commit `333b4c32dc2220a3356e6a4b93f8bd1160a525f5`. Its native source is identical to the former upstream-base-plus-patch delivery. The fork preserves the original native commits and Merman's MIT/Apache-2.0 attribution; these are our changes, not accepted upstream contributions. Cargo dependencies remain locked.

Bootstrap accepts a clean checkout at the pinned commit, including a development symlink, and otherwise fails without resetting or deleting existing work. To update an existing checkout, preserve local work, fetch the fork and explicitly check out the revision in `bootstrap.sh`. Commit and push native changes to `Nek/merman` before updating that pin and verifying Trace. Keep `Latias94/merman` as `upstream`; routine delivery never pushes there. The existing development branch is `feat/sequence-source-mappings`; builds depend on the commit, not its moving branch tip.

While developing uncommitted native changes, bypass bootstrap with `cargo build --manifest-path mermaid-trace-rs/Cargo.toml --locked` and `cargo test --manifest-path mermaid-trace-rs/Cargo.toml --locked`. This permits TDD against the linked checkout before committing; the final `make native-build` must pass with the updated clean pin.

The fork retains the MIT-licensed json5-rs 1.3.1 source and upstream fixtures, adding an opt-in spanned seed to its existing deserializer. Configuration provenance uses that owning parser for exact escaped-key/value ranges, including nested array objects; numeric array indices remain distinct from string object keys. Key selections preserve authored escape bytes and the existing exclusion of quote delimiters. Native configuration/accessibility evidence is nonvisual and does not add keyboard or pointer controls.

Native changes extend Merman's existing LALRPOP grammar, semantic construction and SVG emitter. The regenerated parser is committed in the fork, so normal builds do not need the upstream generator or another parser dependency. When revising the grammar, use Merman's `cargo run -p xtask --locked -- gen-lalrpop-parsers`, then `verify-lalrpop-parsers`. Both use its pinned LALRPOP 0.23.1 generator.

Journey score model compatibility: patched `JourneyRenderTask.score` and `JourneyTaskLayout.score` are `f64`, so Rust model constructors must use floating-point values. Existing integer JSON stays integer; signed zero and fractions retain their values, infinity uses `"Infinity"`/`"-Infinity"`, and NaN keeps the existing zero plus `scoreIsNaN` representation. Native face arithmetic determines whether a score has a renderable visual. Unrenderable scores retain exact property provenance and select their task; they create no phantom controls. See [score conformance](specs/planning-diagrams/spec.md#journey-2-score-numbers-implemented).

Journey geometry retains configured zero width/height and signed task spacing. Raw SVG keeps zero-area rectangles; safe export omits them while preserving source-backed task lines, labels and score controls. See [geometry configuration](specs/planning-diagrams/spec.md#journey-2-geometry-config-implemented).

Journey actor legends retain configured zero/negative wrapping widths and generated hyphen lines. All wrapped lines share the original actor ownership and selection group; UTF-16 hyphenation boundaries serialize lone-surrogate display glyphs as valid UTF-8. See [legend conformance](specs/planning-diagrams/spec.md#journey-2-legend-implemented).

Journey actor names use ECMAScript trimming and UTF-16 ordering in both semantic parsing and render fallback. BOM padding is trimmed; NEL remains part of the name and its exact source range. First-origin legend groups and later task-local circles retain separate ownership. See [Unicode actor semantics](specs/planning-diagrams/spec.md#journey-2-actor-unicode-implemented).

`render(id, source)` returns annotated SVG, the exact source, a source-map projection and semantic identities. Inputs are limited to 50,000 UTF-16 units; IDs use lowercase letters, digits and hyphens and begin with a letter. Invalid input yields an error and does not poison subsequent requests. SVG uses Merman's `resvg-safe` pipeline and bounded local-CLI resource profile. A layout exceeding that profile returns an explicit resource-limit error.

Flowchart, sequence, planning and state diagram mapping use experimental `mermaid-trace/1`. Native `data-mt-key` identities bind source pieces; `data-mt-refs`, `data-mt-role`, `data-mt-start` and `data-mt-end` carry selection ranges. Root `data-mt-map` retains source and the projection. Merman's inert metadata also records original byte spans for native inspection. A label selects its label range. A flowchart connector selects its arrow syntax, including any attached label; a sequence connector selects the message statement. Repeated node references and declarations retain separate occurrences bound to the same visual. Native resolved label provenance identifies the effective declaration, including identical and empty replacements; node and label clicks select that occurrence. Superseded label source selections highlight the semantic node. Nodes without explicit declarations use their first reference. Shape-data and broader directive coverage remain tracked in the flowchart spec. Coordinates in the portable map are zero-based UTF-16 with exclusive ends. Markdown adapters translate them to the original file, including nested fence prefixes.

The [flowchart spec](specs/flowchart-mapping/spec.md#map-native-1-restore-flowchart-behavior-in-rust) and [sequence spec](specs/sequence-mapping/spec.md) record verified constructs and remaining conformance work. The [planning diagram spec](specs/planning-diagrams/spec.md) records Gantt, journey and Kanban selection. Native HTML labels retain their renderer identities through the safe SVG text fallback; no label-text matching is used. The [structural diagram spec](specs/structural-diagrams/spec.md) records state selection and the following class/ER stories. Reverse source selection prefers nested pieces over enclosing ranges. Other families currently have whole-diagram selection only. No all-family support or browser WASM runtime is claimed. [BROWSER-1](specs/sequence-mapping/spec.md#browser-1-future-dynamic-rust-browser-renderer) will expose the same pure Rust rendering path through WASM, optionally in a Worker.

State label identities are emitted alongside the native semantic builder’s accumulated rows (`state:label:<id>:<index>`), so identical description text retains distinct authored ranges. The index belongs to that native row; it is not reconstructed by matching rendered text. Concurrency region rectangles map to their own child-statement blocks; authored separators retain reverse-source relationships. Attached note connectors use the complete note statement as their edge range, with no transition label. Generated note layout containers use inert `data-mt-generated` classification. Nonvisual syntax stays in native metadata. Styles, links and directions add source relationships to existing visuals; clicking still prefers the explicit declaration. Title provenance reuses native YAML token evidence. Safe HTML-label conversion preserves both ancestor and local translations, and only visible converted containers receive activation controls.

The Trace crate enables Merman’s native `layout-elk` and `math` features alongside `svg`. ELK header/configuration selection is verified through saved SVG and the Markdown viewer. These compile-time capabilities do not establish complete family conformance; native formula geometry survives safe HTML-label conversion and saved/live selection tests. The flowchart spec tracks remaining provenance and full variant conformance gaps.

Empty and collapsed flowchart subgraphs retain the same group/frame/title source identity as expanded clusters. Empty ELK frames are sized from native title measurements and configured padding before layout. Legacy `A(-label-)` ellipses render with native SVG or deterministic hand-drawn geometry and ellipse connector intersections; this repairs the pinned upstream renderer's deliberate rejection of that accepted syntax. These fixes do not establish full flowchart conformance: style-created nodes and remaining directive/shape-data/label/variant checks remain in FLOW-2.


Icon, circle/rounded/square icon and image labels carry the same native node-label identity as ordinary labels, including top/bottom placement. Inert `data-mt-generated="asset"` marks icon artwork, whose internal text is not Mermaid label source. Invisible icon bounds helpers use `data-mt-generated="bounds"`; activation disables their pointer interception and restores it on disposal. Static geometry and ordinary node selection remain unchanged.

Plain and Markdown SVG node labels emit one native identity on their visible label group, including wrapped/multiline text. Flowchart projection consumes these identities rather than assigning label spans to arbitrary descendant text. Console `>_` text is marked `data-mt-generated="glyph"`; it selects the enclosing source-backed node and is never an authored label. Empty labels create no label control.

The public flowchart `state` shape shares native rounded-rectangle rendering, with Mermaid's state radius (5, or 3 for neo). Measured label padding produces finite geometry instead of reproducing the pinned JavaScript state renderer's NaN bounds. The parser-owned node, label and property provenance uses the ordinary flowchart path.
