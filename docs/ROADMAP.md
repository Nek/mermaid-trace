# Roadmap

Status: experimental native flowchart, sequence, planning and state diagram producer, independent SVG activation, Markdown provenance a clickable demo and a watch CLI implemented. Stories and criteria are defined in the [spec](specs/source-mapping/spec.md). All built-in Mermaid diagram families are required for the first usable release; see the [coverage gate](specs/diagram-coverage/spec.md). Complete one implementation story at a time without treating implementation slices as reduced product scope.

| Milestone | Scope | Exit evidence | Status |
|---|---|---|---|
| M0 — Foundation | Select and initialize toolchain; establish SDD artifacts | Pinned tools and locked install verified; setup documented | Complete: docs and dependency setup |
| M1 — Feasibility and format | Choose one diagram type; prove spans and artifact v1 alongside Markdown extraction and VS Code preview hooks | Source-backed backend assessment and one representative mapping proof; exact contracts and fixture expectations agreed | In progress: span/SVG/Markdown proofs verified; stable v1 and VS Code selection boundary remain |
| M2 — Static renderer | Implement S1/S6 for every built-in diagram family plus static Markdown integration | Every family passes element/label mapping, reverse lookup, static/saved SVG, exact spans and repeated-occurrence conformance | Incomplete: experimental flowchart subset verified; all-family coverage and export guarantees required |
| M3 — Optional interaction | Implement S2 against saved SVG; first browser demonstration generated by markdown-it | Click/keyboard selection and reverse highlighting work; cleanup, invalid metadata, and multiple-instance isolation verified in a browser | ACT-1 complete for experimental format 0 in pinned Chromium; wider browser/format-v1 acceptance pending |
| M4 — Embedding and viewer | Complete S3 and S4, including unified/rehype; package usable entry points | Plain-JS consumer, HTML Markdown page with multiple blocks, and VS Code webview/editor demonstration; renderer absent from interactivity bundle | In progress: DOC-1 mdast/hast document view and browser selection verified; WATCH-1 minimal file preview added; packaging and VS Code remain |
| M5 — Rust parity | Reuse Merman native core and implement S5 against the agreed format | Shared fixtures pass in both implementations; Rust SVG activates in the same JS library; measured performance with methodology | Native flowchart, sequence, planning and state diagram slices implemented; all-family parity and measured performance pending |

M1 has a [deterministic upstream SVG baseline](specs/svg-baselines/spec.md). The [first mapping proof](specs/flowchart-mapping/spec.md) preserves exact node/edge spans and baseline SVG bytes. Markdown extraction provenance is verified; the stable artifact contract remains open. A renderer that merely places guessed locations in SVG does not satisfy M1 or M2. The legacy reference/mapped-flowchart producer uses Chromium. The selected Merman replacement provides native Rust rendering with flowchart, sequence, Gantt, journey, Kanban and state provenance; remaining families need provenance.

[FORK-1](specs/mermaid-fork/spec.md) replaces parser interception with explicit source maps from [Nek/mermaid](https://github.com/Nek/mermaid/tree/feat/flowchart-source-mappings). [MD-1](specs/markdown-provenance/spec.md) verifies Markdown extraction provenance and synchronous consumption of prepared SVGs. [ACT-1](specs/svg-activation/spec.md) supplies a separate activation module and clickable Markdown demonstration. [DOC-1](specs/document-selection/spec.md) adds the unified mdast/hast document view, rendered-text/heading selection and whole-diagram activation. [WATCH-1](specs/watch-cli/spec.md) adds a minimal live Markdown/Mermaid CLI preview using Vite, with sequence rendering and whole-diagram selection. The selected replacement is [Merman](specs/merman-backend/spec.md), on `feat/merman-backend` in this repository. Native sequence, flowchart, Gantt, user journey, Kanban and state selection slices are implemented; remaining families and conformance gaps follow. Production moves entirely to Merman; legacy runtime compatibility is not a gate, but existing user behavior must survive. All are release requirements. Stable format/security acceptance, reusable package entry points and the VS Code host boundary also remain. Discussing the upstream API remains pending.

## Foundation story: toolchain and initialization

**INIT-1:** approved Node.js LTS + pnpm, strict TypeScript/ESM and Node's built-in test runner. Exact versions, acceptance criteria, implementation plan, and verification live in [the toolchain spec](specs/toolchain/spec.md). Vite now serves the Markdown demo; Playwright verifies browser behavior.

## Later, outside this release

Stable identity across edits, source-rewriting visual editing and collaboration are separate future stories. Dynamic Rust/WASM browser rendering is an agreed future goal under BROWSER-1, after the native mapping foundation.

MERMAN-1 foundation is implemented: separated language directories, pinned native Node adapter, explicit transitional preview routing and native repeatability/lifecycle tests. The native Rust crate now supplies production rendering through a persistent JSON-lines process. SEQ-1 has native, saved-SVG and live clipboard/watch tests. All-family source-map coverage is still pending.

2026-09-26 clarification: production focuses solely on Merman; legacy runtime compatibility is not required; working behaviors must be preserved in Rust. [SEQ-1](specs/sequence-mapping/spec.md) implements native sequence provenance. [BROWSER-1](specs/sequence-mapping/spec.md#browser-1-future-dynamic-rust-browser-renderer) requires future dynamic browser rendering from the same Rust core via WASM, with optional Worker execution and revision-safe updates. Static SVG and separate activation remain mandatory.

[MAP-NATIVE-1](specs/flowchart-mapping/spec.md#map-native-1-restore-flowchart-behavior-in-rust) restores native flowchart node/reference, connector and label selection, including clipboard and optional source-pane behavior. Its regression checks and existing sequence/reference tests pass (6 Rust, 24 TypeScript/browser tests). [Migration principles](DESIGN.md#behavior-preserving-migrations) prohibit removing working behavior or weakening acceptance tests during backend changes. Full family conformance remains required.

Implemented native planning stories: [GANTT-1, JOURNEY-1 and KANBAN-1](specs/planning-diagrams/spec.md), selected by the user. [STATE-1 and STATE-2](specs/structural-diagrams/spec.md) now cover the pinned state-family inventory, including repeated descriptions, concurrency, directives, titles and native renderer variants. Acceptance includes all 286 upstream state fixtures, 48 configuration combinations and saved/live browser selection. Current priority: finish [FLOW-2](specs/flowchart-mapping/spec.md#flow-2-complete-flowchart-family-coverage), then complete sequence, Gantt, journey and Kanban syntax/configuration/occurrence inventories. Subgraphs (including empty/collapsed forms), titles, ELK, safe math-label conversion, repeated declarations and legacy ellipses are implemented. All 1,158 pinned flowchart fixtures render with mapped semantic node/group wrappers and mapped/plain SVG equality. Style-created nodes and style relationships are implemented; default-ID HTML labels now retain exact creation origins. Shape-data statements, scalar labels and property relationships now retain exact YAML provenance. All visible native label containers are included in the mandatory fixture gate. Class/link directive relationships and complete identified-connector spans are implemented; linked HTML labels preserve anchor coordinates. Scoped directions now retain native group relationships, including nested, repeated, empty and collapsed groups. Accessibility statements now retain exact nonvisual metadata and effective title/description origins. Whole frontmatter/directive provenance and exact YAML/JSON5 key/value evidence are implemented, including escaped keys, nested arrays, repeated fields and original-coordinate composition. Icon/image labels now retain native identities across top/bottom placement; generated artwork and bounds no longer create false labels or intercept authored label clicks. Broader property/shape/configuration interactions and complete variant conformance remain open. Class and ER follow the existing-family completion goal. Preserve existing family behavior and keep the full registry coverage gate; smaller commits do not reduce requested family scope.
